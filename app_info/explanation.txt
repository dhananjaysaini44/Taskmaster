TASKMASTER PROJECT DOCUMENTATION
===============================

Welcome to the Taskmaster project! This document provides a high-level overview of the application's architecture, features, and core codebase. It is designed for developers or reviewers who are new to Flutter or this specific project.

1. PROJECT OVERVIEW
-------------------
Taskmaster is a premium, high-performance productivity application built with Flutter. It combines task management, calendar scheduling, and productivity statistics with a high-end "Ambient" user interface. It follows an offline-first philosophy, ensuring speed and reliability even without an internet connection, while providing seamless cloud synchronization.

Key Technologies:
- Flutter & Dart (Frontend Framework)
- Riverpod (State Management)
- Hive (Local NoSQL Database for offline-first performance)
- Firebase Firestore (Cloud Synchronization & Backup)
- GoRouter (Navigation)
- Data Isolation System (Ensures your data is private and separate from other users)

2. SYSTEM ARCHITECTURE
----------------------
The project follows a Feature-First Layered Architecture, which organizes code by "features" rather than technical types. Each feature typically consists of three layers:

- Domain Layer: Contains the Data Models (the "what" of the data).
- Data Layer: Handles storage, retrieval, and synchronization. This layer manages the "Hybrid Storage" logic—instantly saving your data locally so the app feels fast, while simultaneously backing it up to the cloud so you never lose it.
- Presentation Layer: contains the user interface (Screens/Widgets) and the logic that connects the data to what you see on screen.
- Security Layer: A critical component that ensures your data is locked away in a private "vault" on your device, accessible only when you are signed into your specific account.
Directory Structure:
- /lib/core: Global configurations like the theme and routing.
- /lib/features: Individual modules (auth, tasks, calendar, home, profile, splash, settings, mindmap), each following a consistent /data, /domain, /presentation pattern.
- /lib/shared: Reusable UI components used across multiple features.

4. SCREEN FUNCTIONALITIES
-------------------------

A. Splash Screen
A cinematic entry point that handles the initialization of the application and displays the Taskmaster branding for a premium first impression. Now features theme-aware background images (`splash_bg_light.png` and `splash_bg_dark.png`) for a cohesive launch experience.

B. Login Screen
A clean, center-aligned branding page that supports secure authentication via Firebase. The screen utilizes dynamic background assets that adjust based on the current system theme.

C. Tasks Screen
The high-fidelity Kanban-style hub for productivity, focusing on granular task interactions.
- Filtering: View "All", "Upcoming", or "Completed" tasks.
- Interaction: 
  * Tap to Edit task details or notes.
  * Check the circular box to mark as complete.
  * Long-press to delete (with confirmation).
- Organization: Intuitive Kanban columns with full Drag & Drop support. Move tasks between statuses instantly with persistent reorder handles. Changes are synced instantly to the cloud.

D. Calendar Screen
A visual schedule and performance tracker for your commitments.
- Focus Flow Header: Displays the full ordinal date (e.g., "March 21st") and a dynamic themed counter for pending events.
- Interactive Calendar: View and manage events for any selected day.
- Event Management: Add, Edit, Delete, or toggle completion for events.
- Streak Tracking: An integrated dashboard counts weekly completed events and displays your current productivity streak.
- Cloud Sync: Real-time Firestore synchronization keeps your schedule consistent across all devices.

E. Home Screen (Intelligence Dashboard)
The primary landing experience and analytics hub.
- Personalized Greeting: Displays dynamic greetings based on your profile and time of day.
- Completion Metrics: High-fidelity visualizations (charts) derived from both tasks and events.
- Upcoming Deadlines: An expanded list of up to 10 entries merging tasks and events, allowing for direct completion toggling from the dashboard.
- Direct Navigation: Tapping the user profile header redirects instantly to the Profile management suite.
- Refined Layout: Optimized vertical spacing and interactive elements for a premium "Ambient" feel.

F. Profile & Settings Screen
Manage your identity and application environment.
- Identity Management: The new Profile Suite allows users to update their Display Name and secure their account with Password modifications.
- Sync Status: Provides transparency on the synchronization state between the local vault and the cloud.
- Interface Customization: Switch between Light and Dark mode with a seamless "Ambient Background" transition and language selection.

G. Native Notification System
A proactive reminder engine that keeps you on track.
- Lead Time: Sends reminders exactly 30 minutes before a task's deadline or an event's start.
- Smart Lifecycle: Notifications are automatically canceled if a task is deleted or marked as completed.
- Persistence: Uses advanced alarm scheduling to ensure reminders work even after a device reboot.

5. IMPORTANT CODE SNIPPETS & PATTERNS

A. State Management (Riverpod)
We use Riverpod to keep the UI in sync with the data sources.
Example from `tasks_provider.dart`:
```dart
@riverpod
class TasksProvider extends _$TasksProvider {
  @override
  Stream<List<TaskModel>> build() {
    return ref.watch(taskRepositoryProvider).watchTasks();
  }
}
```
*Explanation*: This provider "watches" the storage. Whenever a task is updated locally or synced from the cloud, the UI updates automatically.

B. Hybrid Persistence (Hive + Firestore)
Data is saved locally for speed and synced to the cloud for reliability.
Example pattern from `task_repository.dart`:
```dart
Future<void> addTask(TaskModel task) async {
  // 1. Save locally to Hive for instant UI feedback
  final box = await Hive.openBox<TaskModel>('tasks');
  await box.put(task.id, task);

  // 2. Sync to Firestore in the background
  final user = _auth.currentUser;
  if (user != null) {
      await _firestore.collection('users').doc(user.uid)
          .collection('tasks').doc(task.id).set(task.toMap());
  }
}
```
*How it works*: Imagine the app has a local "Notebook" (Hive) that it writes in immediately so you don't have to wait. At the same time, it sends a copy to a "Cloud Safe" (Firestore). If you get a new phone, the app just downloads everything from your "Cloud Safe" back into a new local "Notebook."

D. Data Isolation & Privacy (Your Private Vault)
The application implements a strict "Private Vault" architecture to ensure data integrity and confidentiality, especially on shared devices.

*   **UID-Prefixed Local Vaults (Hive)**: The application dynamically initializes storage based on the user's unique Firebase ID (`UID`). Every user's data is stored in a separate, encrypted-ready Hive box (e.g., `tasks_{uid}`). This ensures that even if another user logs in on the same device, they have zero access to the previous user's local data.
*   **Logout Sanitization**: Upon logout, the application performs a complete "Memory Flush," closing all user-specific boxes and resetting providers to their initial, empty states.
*   **Cloud Folders (Firestore)**: In the cloud, data is segmented into `users/{UID}` sub-collections. Firebase Security Rules restrict access so that only the owner of the UID can read or write to their corresponding "folder."

*Simple Explanation*: Taskmaster treats your data like a safety deposit box. Your key (Login) only opens your box. Even in the same "bank" (App), everyone has their own locked compartment that no one else can touch.

5. NATIVE NOTIFICATION SYSTEM & SCHEDULING
The system implements a precise scheduling strategy using `flutter_local_notifications` and `timezone` to ensure reminders are accurate across different regions.

A. Scheduling Logic
When a task or event is added/updated, the application calculates the trigger time: `ScheduledTime - 30 Minutes`. If this calculated time is in the past, no notification is scheduled.

B. Lifecycle Management
- **Creation**: Scheduling occurs immediately upon successful local save (Hive).
- **Completion**: Marking a task/event as done triggers `cancelNotification(id)`, removing the pending alert from the system tray.
- **Update**: Modern "Upsert" logic cancels any existing notification for that ID before scheduling a new one based on the updated time.

C. Platform Reliability
The system is configured with high-priority channels and `SCHEDULE_EXACT_ALARM` permissions to ensure timely delivery on newer versions of Android where battery optimizations often delay background tasks.

6. GETTING STARTED
------------------
To run the project locally:
1. Ensure Flutter is installed.
2. Run `flutter pub get` to install dependencies.
3. Run `dart run build_runner build` to generate data adapters.
4. Launch via `flutter run`.
