TASKMASTER PROJECT DOCUMENTATION
===============================

Welcome to the Taskmaster project! This document provides a high-level overview of the application's architecture, features, and core codebase. It is designed for developers or reviewers who are new to Flutter or this specific project.

1. PROJECT OVERVIEW
-------------------
Taskmaster is a premium, offline-first productivity application built with Flutter. It combines task management, calendar scheduling, and productivity statistics with a high-end "Ambient" user interface.

Key Technologies:
- Flutter & Dart (Frontend Framework)
- Riverpod (State Management)
- Hive (Local NoSQL Database)
- GoRouter (Navigation)

2. SYSTEM ARCHITECTURE
----------------------
The project follows a Feature-First Layered Architecture, which organizes code by "features" rather than technical types. Each feature typically consists of three layers:

- Domain Layer: Contains the Data Models (the "what" of the data).
- Data Layer: Handles storage and retrieval (Repositories).
- Presentation Layer: Contains the UI (Screens/Widgets) and State Management (Providers).

Directory Structure:
- /lib/core: Global configurations like the theme and routing.
- /lib/features: Individual modules (auth, tasks, calendar, stats, profile).
- /lib/shared: Reusable UI components used across multiple features.

4. SCREEN FUNCTIONALITIES
-------------------------

A. Splash Screen
A cinematic entry point that handles the initialization of the application and displays the Taskmaster branding for a minimum of 3 seconds for a premium feel.

B. Login Screen
A clean, center-aligned branding page. While currently using "mock" authentication, it provides the structural foundation for secure user entry.

C. Tasks Screen (Main Dashboard)
The primary hub for productivity.
- Filtering: View "All", "Upcoming", or "Completed" tasks.
- Interaction: 
  * Tap to Edit a task.
  * Check the circular box to mark as complete.
  * Long-press to delete (with confirmation).
- Organization: Drag and drop tasks using the explicit reorder handles on the right.

D. Calendar Screen
A visual schedule of your commitments.
- Interactive Calendar: View events specifically for the selected day.
- Event Management: Add, Edit, Delete, or mark events as completed.
- Custom Styles: Choose from standard categories (Work, Gym, Personal) or create your own with custom colors.

E. Stats Screen
A dynamic dashboard for tracking progress.
- Completion Metrics: Real-time calculation of your task and event productivity.
- Interactive Deadlines: View and toggle upcoming tasks directly from the statistics view.

F. Profile & Settings Screen
Manage your identity and preferences.
- Theme Toggling: Switch between Light and Dark mode with an "Ambient Background" effect.
- Notifications/Language: Structural settings for future expansion.

5. IMPORTANT CODE SNIPPETS & PATTERNS

A. State Management (Riverpod)
We use Riverpod to keep the UI in sync with the data. 
Example from `tasks_provider.dart`:
```dart
@riverpod
class TasksProvider extends _$TasksProvider {
  @override
  Stream<List<TaskModel>> build() {
    return ref.watch(taskRepositoryProvider).watchTasks();
  }
}
```
*Explanation*: This provider "watches" the database. Whenever a task is added or edited, the screen UI updates automatically everywhere.

B. Local Persistence (Hive)
Data is saved locally using Hive boxes. This ensures the app works perfectly without an internet connection.
Example from `task_repository.dart`:
```dart
Future<void> updateTask(TaskModel task) async {
  final box = await Hive.openBox<TaskModel>('tasks');
  await box.put(task.id, task);
}
```
*Explanation*: This saves the `TaskModel` to a local file on the device.

C. Premium UI (Ambient Background)
The app uses a custom `AmbientBackground` widget that blends gradients and theme-aware images behind the content.
```dart
class AmbientBackground extends StatelessWidget {
  final Widget child;
  // ... builds a stack with themeaware images and glassmorphism effect
}
```

6. GETTING STARTED
------------------
To run the project locally:
1. Ensure Flutter is installed.
2. Run `flutter pub get` to install dependencies.
3. Run `dart run build_runner build` to generate data adapters.
4. Launch via `flutter run`.
